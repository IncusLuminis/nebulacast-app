# Codebase audit — 2026-09-07

## Completed: lunar data contract

The phase was independently calculated in the hero, Sun Equation, sky canvas,
the Pages API, the static generator, and legacy weather maps.  The meanings of
`phase` also differed: some code treated it as the lunar-cycle position while
other code treated it as illuminated area.  The Pages API even inverted the
illumination formula, making a new moon read as a full moon.

`frontend/astronomy/lunar.ts` is now the sole source for lunar phase data. It
uses `astronomy-engine@2.1.19`, has a UTC-minute cache, and returns a named
contract: cycle phase, illuminated fraction/percentage, waxing direction,
phase name and emoji. It is bundled for the browser and Pages Functions, and
the Python static generator invokes the same bundled implementation.

The hero, Sun Equation and sky canvas now consume that contract. Legacy map
views also use it. `sun_moon.json` version 2 records its source and preserves
DE421 only for position/altitude data.

Regression coverage compares 16 2026 primary phases with USNO's published
times, checks DE421 illuminated fractions, location timezones/DST, the API,
the Python batch bridge, stale static frames, and the Sun Equation day picker.

## Prioritized follow-up work

### P0 — make ephemeris location ownership explicit

`services/weather/pipelines/fetch_weather.py` and
`services/weather/normalizers/observer_weather.py` read the static Warsaw
`sun_moon.json`. This is valid only for the configured Warsaw pipeline. It
must never become the fallback for a user-selected location. Pass location into
an ephemeris provider or label the payload as Warsaw-only; keep the existing
location-aware `/api/sun-moon` path for browser users.

### P0 — repair the TypeScript quality gate

`npx tsc --noEmit` currently fails before these changes: untyped JSON from
Open-Meteo and Nominatim, a nullable response path, and Node test globals not
included in `tsconfig.json`. Add schema validation at provider boundaries and
split the Node test config from Pages Function compilation. This will make a
required CI typecheck meaningful.

### P1 — eliminate parallel page implementations

`sites/staging/weather/map-poc.html` (5,340 lines) and `map1.html` (2,882
lines) duplicate weather-map and lunar display behavior. The root console
page is also 5,070 lines. Extract their scripts into versioned ES modules and
retain a single map entry point. This prevents display fixes from being copied
across pages.

### P1 — centralize ephemeris interfaces

SunCalc remains appropriate for local horizon events, but every consumer should
receive `{time, position, lunar state}` through one typed adapter. Define the
JSON schema and reject incompatible versions rather than permissively treating
`phase` as either percent or fraction.

### P1 — add CI checks before deployment

The deploy workflow deploys the tracked staging tree without building or
testing it. Add a PR workflow that runs `npm ci`, `npm run build:functions`,
`npm run test:lunar`, Python unit tests, JSON contract validation, and a small
browser smoke test. Keep the deploy workflow as the final artifact upload.

### P2 — reduce repeated request work and unbounded DOM lifetimes

The main console, weather widget and sky widget each fetch overlapping data and
start independent refresh/listener paths. Introduce a request registry keyed by
location and data freshness, with `AbortController` on location changes. Make
each widget return a mandatory dispose function and call it during remount.

### P2 — dependency and security hygiene

`npm audit` reports one moderate issue in `esbuild@0.24.x` affecting a local
development server. Upgrade it in a dedicated compatibility PR, then re-run
the functions build and local development smoke test. Do not use automatic
major upgrades without that check.

### P2 — pipeline consistency and observability

The scheduled pipelines independently write and commit related generated data.
Introduce a common generator manifest containing schema version, input source,
generation time and location; validate it before commit. Add structured
failure output for upstream provider errors so stale data is visible in the UI.
