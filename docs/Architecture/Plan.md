Супер, у нас уже сейчас из одного daily_astro_weather.json можно показывать довольно много — и это реально "near real time" (по сравнению с RSS). Вот что уже есть в JSON и что можно добавить с небольшой доработкой.  ￼

⸻

Что уже можем показывать прямо сейчас (из текущего JSON)

В файле есть:

1) Почасовая "астро-погода" на 72 часа вперёд

Массив hours[], где на каждый час есть:
	•	cloud_total, cloud_low, cloud_mid, cloud_high — облачность по слоям (%)
	•	precip_mm, precip_prob — осадки и вероятность
	•	pressure_hpa — давление
	•	wind_m_s — ветер (в м/с)
	•	visibility_m — видимость (в метрах)
	•	seeing и transparency — качество "seeing"/прозрачности (шкала у вас уже есть)
	•	score — итоговый интегральный "астро-скор" 0–100  ￼

То есть карточки по часам (как у тебя на скрине) — это уже полностью оправдано данными.

2) "Now" (текущее состояние)

Берём ближайший к текущему времени час и показываем:
	•	текущий score
	•	ключевые факторы: облачность, ветер, видимость, seeing/transparency, осадки, давление  ￼

3) "Best observing windows"

В summary.best_windows[] уже есть "лучшие окна" с:
	•	start, end
	•	score_avg
	•	label (например, "Fair")  ￼

Это позволяет красиво показывать:
	•	"Tonight best window …"
	•	"Top 3 windows ближайших 72 часов"

4) Быстрые "сигналы" для астронома (без доп. источников)

Из тех же полей можно сразу выводить мини-индикаторы:
	•	Облака: total + разбиение по слоям (для астрофото особенно важно low/mid vs high)
	•	Ветер: высокий ветер часто = плохой seeing/трясёт трубу
	•	Прозрачность/seeing: уже готовые оценки
	•	Видимость: туман/дымка сразу будет видно по visibility_m
	•	Давление: тренд давления (см. ниже "доработки")  ￼

Важная ремарка (уже сейчас надо учитывать)

Иногда seeing и transparency бывают -9999 (пропуск/нет данных). UI должен:
	•	не ломаться
	•	показывать — и не учитывать эти поля в подсчётах/цветах, если они отсутствуют  ￼

⸻

Что сможем показывать при небольшой доработке (всё ещё на базе этого JSON)

A) Нормальный "ночной" режим (самое важное улучшение)

Сейчас "best window" может попасть на дневные часы — потому что данные идут сплошняком.

Доработка: добавить вычисление Sun altitude и фильтровать окна по условию, например:
	•	астрономическая ночь: sun_alt <= -18°
или хотя бы:
	•	"тёмно": sun_alt <= -6°

И тогда:
	•	"Tonight best window" действительно будет ночью
	•	карточки можно подсвечивать "Night / Twilight / Day"  ￼

B) Луна (вторая ключевая вещь после облаков)

Добавить в JSON на каждый час:
	•	moon_alt (высота Луны)
	•	moon_illum (освещённость, %)
	•	moon_phase (название/фаза)
	•	опционально: moon_sep_target пока не нужно, но можно позже

Тогда можно честно считать "visibility score" для:
	•	визуальных наблюдений (планеты/ДСО)
	•	астрофото (особенно narrowband vs broadband)

C) Тренды и предупреждения ("падающее давление", "влажность растёт")

Сейчас есть pressure_hpa, но нет производной.

Добавить в summary:
	•	pressure_trend_6h (hPa/6h)
	•	wind_peak_next_24h
	•	cloud_peak_next_24h
	•	fog_risk (из видимости + высокой влажности, если добавим humidity)

UI-эффект: одна строка "Heads-up на ночь":
	•	"Clouds increase after 23:00"
	•	"Wind peaks 02:00–04:00"
	•	"Possible haze/fog"  ￼

D) Разные "профили" наблюдений (переключатель)

На базе тех же полей можно сделать 2–3 режима скоринга:
	•	Visual (важнее clouds_total, moon, transparency, wind умеренно)
	•	Astrophotography broadband (важнее transparency + moon + clouds_high)
	•	Planetary (seeing + wind + clouds_total)

Это чисто математическая переработка в fetch_astro_weather.py/агенте и 1 переключатель в UI.  ￼

⸻

1️⃣ Псевдо-реалтайм спутниковые снимки облаков (то, что видно прямо сейчас)

🔹 Лучший вариант для Европы (включая Варшаву)

EUMETSAT / Meteosat (MSG)

Что даёт:
	•	обновление каждые 5–15 минут
	•	видимый, инфракрасный, water vapor
	•	отлично показывает:
	•	фронты
	•	движение облаков
	•	прояснения ночью (ИК!)

Как использовать у нас:
	•	брать готовые PNG/tiles (без API-ключей)
	•	отображать как:
	•	📡 "Clouds now"
	•	⏩ анимацию за последние 6–12 часов

➡️ идеально для Sky Alerts / Weather вкладки

⸻

🔹 Глобальный вариант

NOAA / GOES
	•	хуже для Европы (край зоны),
	•	но полезно, если потом пойдёте глобально.

⸻

2️⃣ Облачный радар + прогноз движения (не просто "картинка")

🔹 Open-Meteo (ты его уже косвенно используешь 👌)

Open-Meteo

Плюсы:
	•	бесплатный
	•	JSON
	•	можно брать:
	•	cloud cover по слоям
	•	давление
	•	ветер
	•	осадки
	•	почасово, обновляется часто

Минус:
	•	нет "живых" спутниковых картинок

➡️ Отлично для расчётов и score, но не для "вау-визуала".

Отличный момент — карта тут может стать вторым мозгом после скоринга, а не просто фоном. Давай системно.

Ты уже правильно задал базу:

Центр карты = выбранная локация
Terrain + облачный слой сверху

Это must-have. Дальше — что можно добавить принципиально, слоями, не превращая карту в свалку.

⸻

Базовый слой (MVP, без перегруза)

1. Облачность (обязательно)

Что:
	•	Cloud total (основной слой)
	•	Опционально: low / mid / high как toggle

Зачем:
	•	Мгновенно видно, откуда и куда ползёт облачность
	•	Понимание «через 2 часа будет хуже» без графиков

UX:
	•	Полупрозрачный слой
	•	Анимация «+1h / +3h / +6h» (таймлайн или scrubber)

⸻

2. Night mask (очень важно для астрономии)

Что:
	•	Зона ночи / астрономических сумерек
	•	Терминатор (граница дня/ночи)

Зачем:
	•	Сразу видно: наблюдать вообще можно или нет
	•	Особенно полезно при смене локации

UX:
	•	Тёмный оверлей
	•	Лёгкий градиент, не «убивающий» карту

⸻

Слои «астро-смысла» (вторая очередь)

3. Moon overlay

Что:
	•	Положение Луны
	•	Освещённость (glow radius)
	•	Высота над горизонтом (цвет/иконка)

Зачем:
	•	Понимание засветки неба
	•	Ключевой фактор для фото / DSO

UX:
	•	Круг мягкого света
	•	Tooltip: Moon altitude, phase, illumination

⸻

4. Transparency / Seeing heatmap (killer feature)

Что:
	•	Условная карта качества:
	•	Transparency (DSO)
	•	Seeing (planetary)

Зачем:
	•	Понять, куда стоит поехать на 30–50 км
	•	Не только «как у меня», а «где лучше рядом»

UX:
	•	Heatmap
	•	Toggle: Seeing | Transparency

⚠️ Не идеально точно — но достаточно полезно.

⸻

Метео-динамика (третья очередь)

5. Ветер (стрелки)

Что:
	•	Направление + скорость
	•	Особенно у земли и на высоте (если есть данные)

Зачем:
	•	Вибрации телескопа
	•	Турбулентность → seeing

UX:
	•	Тонкие стрелки
	•	Плотность = сила ветра

⸻

6. Давление (изобары)

Что:
	•	Изобары + тренд

Зачем:
	•	Косвенный признак стабилизации / деградации погоды

UX:
	•	Очень тонкие линии
	•	Выключено по умолчанию

⸻

Астрономические объекты (очень вкусно)

7. Visible sky objects (опционально)

Что:
	•	Зенитная сетка
	•	Направления на:
	•	Млечный Путь
	•	Планеты
	•	Яркие DSO (по желанию)

Зачем:
	•	Связать карту Земли и карту неба
	•	Понять, «в какую сторону смотреть»

UX:
	•	Только стрелки / азимуты
	•	Не полноценный планетарий (это другая вкладка)

⸻

Пользовательские слои (позже)

8. Light pollution (Bortle)

Что:
	•	Статическая карта засветки

Зачем:
	•	Выбор локации
	•	Планирование поездок

⸻

9. User markers

Что:
	•	«Мои места наблюдений»
	•	Последняя выбранная точка
